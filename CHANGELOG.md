# Changelog

## Unreleased

- New `keygraph demo [--dir DIR] [--no-open] [--json]` (so `uvx keygraph demo` works): builds the bundled 35-table webshop into `./keygraph-demo` with the core install only, in this process (no subprocess). The demo data now ships inside the wheel (`keygraph/demo/`; `context.json` is generated from `examples/shop/context.yaml`, and a test keeps the copies identical), profiles read the bundled SQLite sample through the standard library, and steps an extra would improve use a simpler reader and print a note naming the extra (a missing sqlite3 skips profiles). It opens `keygraph.html` unless `--no-open`, `CI` is set or there is no display, prints three commands to try, refuses a non-empty folder that is not an earlier demo, and a rerun gives byte-identical `graph.json`, pages and `keygraph.html` (`keygraph.db` holds write times; `SOURCE_DATE_EPOCH` honoured). The `profile_table` function takes an optional `now` for a fixed `profiled_at`.
- `keygraph index start|next|submit|status|finish|replay|refresh` (each with `--dir` and `--json`) and the MCP tools `index_start`, `index_next`, `index_submit`, `index_status` and `index_finish`: your own agent builds the meaning layer through a work queue, and keygraph validates, probe-checks and stores every answer (see the entry below for the store and replay layer). `keygraph doctor` expects the five tools, and the MCP server lists 20 tools (21 with dev mode on at start).
- Output format additions from LLM indexing (nothing changes for a map without indexed answers):
  - `graph.json` can hold edges with `source: "llm"`, an `llm_boost` field on an inferred edge that an LLM relation confirms. `graph.json` is unchanged for a map built without indexing: the rejected pairs of an overrides file live in `keygraph.db` (table `override_rejects`), not in `graph.json`.
  - `describe` (CLI and MCP) gains `performance` and `provenance`.
  - The MCP server has 5 new tools (`index_start`, `index_next`, `index_submit`, `index_status`, `index_finish`): 20 tools, 21 with dev mode.
  - `keygraph.db` gains the `index_jobs`, `index_units`, `index_relations`, `performance_notes` and `override_rejects` tables and a `fact_provenance` table.
- Behaviour of the LLM indexing loop:
  - `index finish` and `index replay` refuse when the map was rebuilt since `index start` (the schema in `graph.json`, compared by table and column ids, differs from `index/base_graph.json`) and say to run `keygraph index refresh`, which re-snapshots the base and re-plans. Before, a rebuild followed by `finish` silently reverted new tables.
  - Text an LLM filled into an empty field of a human note is labelled `llm` and unverified: `describe` provenance gains `filled` (`{"notes": {field: {label, verified}}, "columns": {col: {field: ...}}}`), the text output marks those fields `(llm)`, and `search` results gain `llm_fields` and report `verified: false` for such a table.
  - An unverified LLM relation never raises the confidence of an existing edge (it adds an evidence line only). A probe-verified one raises it to max(current, 0.9), never for an edge a probe lowered (`status: probed`). LLM `concept_links` on a concept a person wrote are skipped and counted as kept.
  - `submit` refuses an answer that does not fit the budget left: `{status: "budget_exhausted", needed, budget_left, hint, resume}`, nothing stored and no attempt used, so `used` never exceeds `budget`. MCP `index_submit` gains `probe_seconds`, like the CLI `--probe-seconds`.
  - When the job names a probe variable that is not set in the shell that runs `submit`, the reply says `probe_source: "missing: NAME is not set in this shell; items stored unverified"` (it was `unset`). A probe verdict that checked nothing (`n: 0`, `verified: null`) carries a short `why`, for example `no non-null values sampled`.
  - Honest confidence: a codes probe that finds every claimed code value in the data now records `verified: null` with `seen: true` (answer files from before this change, `verified: true` with check `codes_present`, count the same). It is shown as `llm, codes seen in data`, never as `verified by probe`; that label stays for checks of the claim itself (relation overlap, table grain uniqueness, default-filter selectivity). `submit` and `status` report `codes_seen` apart from `verified`, `verify_rate` counts only probe-verified items, and `finish` and `replay` add `codes_seen_facts` next to `verified_facts`. `search` table results gain `provenance`.
  - Every `verified: null` verdict carries a `why`, including no codes, no filters, the query cap, a failed query, a spent time budget and kinds that are not probed. The answer schema allows an empty meaning for a code, and the instructions and SETUP.md say never to invent a code label.
  - `index start` (and every other index command) refuses a `keygraph.db` built by an older keygraph (no `override_rejects` table) before the schema is applied: rebuild it with `keygraph build`, `scan` or `load` first.
  - The describe text and `describe --brief` mark every LLM-written field `(llm)`, grain included.
  - A sampled value that contains dollar quoting (a `$2b$` hash) is skipped by `keygraph probe` and the index probes instead of failing the whole query.
- Changes outside indexing that came with this branch:
  - `assert_select` is stricter: it refuses `;` inside quoted text, any backslash, dollar quoting (`$tag$`), `E'..'` strings and unterminated quotes.
  - `sqlite:` URLs run through a stdlib read-only runner (`mode=ro`), so `profile` and `probe` on SQLite no longer need the `live` extra, and a bad `sqlite:` URL exits with a message, not a traceback.
  - The MySQL chunked metadata fetch now uses `LIKE ... ESCAPE '!'` (`adapters/fetch.py`).
- `index submit` replies gain `confirmed_existing`: how many accepted relations repeat an edge the map already has (a repeat adds evidence only). The answer instructions say not to repeat declared or inferred relations.
- `docs/dev-mode.md` lists the `index_*` dev events and their privacy rule (ids, counts and check names only).
- Agent docs: README has a section "LLM indexing (recommended for agents)"; AGENTS.md, `llms.txt`, the skill and `setup/SETUP.md` (new optional step 4b) describe the loop, the attempt rules and the env-var-only probe source, and the tool counts now read 20 (21 with dev mode). No accuracy or speed figures are claimed: none are measured yet. The deterministic map stays the default until a benchmark shows a lift.
- Replay from a fresh checkout is deterministic, but code-join and business-context evidence live in `keygraph.db` and the context files: commit the context files next to `index/answers/`.
- Loop: `start` (needs a built map, saves `index/base_graph.json`, groups the tables into units, sets a token budget with `--budget`, default 200000; `--tasks` and `--max-units N` limit the work), then `next` and `submit` until `next` says `done`, then `finish`. `next` returns the same unit until it is submitted; with too little budget it returns `budget_exhausted` with the unit id and a `start --budget N` command to continue (smaller units later in the queue are skipped on purpose). A second `start` resumes the open job; `--restart` starts over and keeps saved answers.
- Submit: `accepted`, `partially_accepted`, `rejected` or `failed`, always with a `next` hint. Accepted items are stored at once; when some items are rejected the unit stays pending, and the agent resubmits only the rejected items (the saved answer is the union). Each rejected or partial submit uses one of three attempts and the third fails the unit, which keeps the deterministic map. A missing answer file is an error (exit 2, JSON error object with `--json`) and uses no attempt; so are the first three unparseable answers per unit, after that they count as attempts. A `failed` reply says the unit keeps the deterministic map and earlier accepted items stay stored. The packet is charged once per unit, then each submit costs its answer.
- Probe source: `--url-env NAME` or `--cmd-env NAME` names an environment variable holding the probe database URL or a read-only `{sql}` command. keygraph stores and logs only a valid name (never what was typed), reads the value when `submit` runs, and the MCP tools take names only. Probes have a wall-clock budget per submit (`--probe-seconds`, default 60); when it is spent the remaining items stay unverified with check `time_budget`. A query already running is not cancelled, so one slow query can overrun it.
- The CLI `--json` output and the MCP tools return identical JSON: hints such as `next` name both forms (`index_next (CLI: keygraph index next)`). The answer file is written first, then the facts and the unit status are committed; replay ignores a file from a submit that never committed, and `finish` fails clearly when a done unit has no answer file. Performance notes of a resubmit are merged (union per table), so the live database and a replay agree.
- After the run: `status` shows progress, budget, accept and verify rates and failed units; `finish` runs the replay (so `finish` and `replay` write byte-identical `graph.json`, pages, report and explorer) and closes the job; on a finished job `next` and `submit` return `finished` with what to run. `refresh` re-plans after the map changed: it puts back failed units and units whose packet changed, adds new units and drops removed ones with their saved answers.
- Dev mode logs each index command with unit ids, packet size estimates, validation counts and probe verdict counts, never values, reasons or answer text. `keygraph.db` gains a `dialect` column on `index_jobs` (added when an older file is opened for writing).
- LLM indexing, store and replay layer (no new command yet; the `keygraph index` commands arrive with the CLI step). Accepted answers are stored in `keygraph.db` with a `fact_provenance` row each and saved as `index/answers/<unit_id>.json`; `index.replay.replay` rebuilds the meaning layer from them with no model and no database access, and `finish` adds `index/summary.json` (counts only). LLM facts fill empty fields and replace older `llm` rows; they never change a row a human wrote. Output change: `graph.json` can hold edges with `source: "llm"` (evidence starts with `llm: `, confidence at most 0.75, or 0.9 after a passed probe; a failed probe stays out of the graph), and an inferred edge that an LLM relation equals gains the evidence and an `llm_boost` field recording the raise. Output change: `describe` (CLI and MCP) gains `performance` and `provenance` (labels `llm`, `llm, verified by probe`, `deterministic`, `declared`, `verified`; relations get a `provenance` field), and the text output shows performance notes. `index_relations` gains a `cardinality` column. The reject overrides of a build are kept in `keygraph.db` (table `override_rejects`), so an LLM relation never brings a rejected edge back and `graph.json` gains no key for them. An older `keygraph.db` gets the `cardinality` column added when it is opened for writing.
- Inference recovers more foreign keys in databases that declare none. Five naming-gap rules, each named in its edge's evidence: (a) a column of any name equal to the single-column primary or unique key of exactly one other table (not generic names such as `name`, `code`, `email`, `mobile` or `version`, and not `*_name`, `_title`, `_description`, `_label` unless it is a primary key); (b) `link_to_`, `ref_`, `fk_` and `id_` reference prefixes; (c) numbered role columns (`home_player_1`, `away_player_2`), pointing at a surrogate table's named key and never at its surrogate id when named keys exist, with weak ambiguous edges when several named keys fit; (d) `<table>_<column>` and camelCase names (`setCode` for `sets.code`); (e) a bare `id` column in a table with no key of its own. When two of these rules find the same target, the strictest cap applies and the edge keeps one key. On the 11 BIRD mini-dev databases (104 declared FKs, stripped) recall rises from 48.1% to 54.8% at confidence >= 0.8 (precision 92.6% -> 93.4%) and from 52.9% to 65.4% at >= 0.6 (91.7% -> 93.2%). The gain at >= 0.8 comes from `link_to_` edges in one database (`student_club`). On 30 Spider2-Lite databases recall at >= 0.6 rises from 69.7% to 73.0% and precision falls from 50.4% to 49.1%; nothing changes at >= 0.8. Spider2-Lite is not a held-out set (its extra edges were inspected while tuning). Precision is a lower bound. Method and results: `bench/README.md`.
- Output change: `scan` and `load` can add new inferred edges on databases that declare few foreign keys, and join paths can use them. Confidence by rule (decision dec-012): name-only evidence stays below 0.8. Rules (a) and (e) and the `id_`/`ref_` prefixes are capped at 0.75, and so are (c) and (d), unless the column types match exactly and the source column is the leading column of an index, which can lift (c), (d), (e) and `id_`/`ref_` edges to about 0.9 or 0.95. `link_to_` and `fk_` edges are not capped and score like the `_id` rule (0.9 or more with matching types). Rebuild maps after upgrading and check any edge below 0.8 with `keygraph probe`.
- Output change: `context add` now merges into an existing row. Fields you do not give keep their stored values (before, the whole row was replaced and codes or null meanings were lost); a field given with an empty value (`codes=`) clears it. `context import` and `import-notes` still write whole rows. History records the old row and the merged one. `codes=` merges code by code, links nested in a concept merge too, and list fields (`synonyms`, `tables`, `recommended_indexes`) are replaced as a whole. A missing key field (for example no `column=`) is now a clear error. Known: a link nested in a concept does not inherit the concept's `verified` flag.
- Output change: `neighbors` and `describe` (CLI and MCP) now hide relations below 0.6 confidence by default and say how many they hid (`hidden` in `neighbors`, `hidden_relations` in `describe`, plus a one-line hint in text output). `--min-confidence N` on both commands (MCP `min_confidence`) changes the floor; `0` shows everything, as `neighbors` did before. `describe --brief` is unchanged.
- Context history: every write that replaces a row with different content, and every unverified write refused because a verified row exists, is recorded in a new `context_history` table (old and new row, source, time). Identical re-imports add nothing. `keygraph context history [--ref R] [--kind K] [--limit N] [--json]` lists it, newest first. `context add --author NAME` (or `KEYGRAPH_AUTHOR`) sets who wrote it. History and CLI context adds live in `keygraph.db`, so deleting or rebuilding the output folder from scratch loses them; `context export` saves the notes but not the history. A repeated refused write with the same content adds no new row. Output change: the default source label of `context add` is now `context-add` instead of `agent`; a `source=...` field still wins.
- `context add` honours `--verified`, and `context add`, `import` and `import-notes` count only rows actually written; the JSON gains a `kept` object for verified rows that were kept. The Postgres scan filters schemas in its SQL, every metadata query that returns exactly its row limit prints a warning, `build.json` names the engine (`sqlite`, `postgres (generic)`), and the unknown-table hint fits the build type. `examples/shop/build.sh` works from any folder.
- `keygraph doctor` has a `metadata` check that counts the layers the map has (column comments, enum columns, row estimates) and warns, with a fix, when it has none. `doctor --json` gains a `graph.metadata` object.
- Smaller answers on request: `keygraph describe T --brief` (MCP `describe` with `brief=true`) returns keys, filter columns, notes and columns as name, type, key and codes only, with no profiles or relations; `keygraph search --no-paths` (MCP `search` with `with_paths=false`) leaves out the suggested join paths. CLI and MCP return the same JSON.
- `keygraph scan --url` now uses the dedicated adapter for MySQL/MariaDB, PostgreSQL, SQL Server and ClickHouse URLs (still SELECT-only), so scanned maps keep column comments, enum members, row-count estimates and partitions like `load` does. `--schema` and `--all-schemas` behave as before; SQLite and other databases keep the SQLAlchemy inspector, an adapter error falls back to it with a stderr warning, and the new `--generic` flag forces it. `build.json` records the path used.
- New `build.json` next to `graph.json` (build time, keygraph version, source kind and database or dump file names, covered schemas; never a URL, host, credentials or absolute path; `SOURCE_DATE_EPOCH` sets the time). An unknown-table error now says which schemas the map covers and when it was built, and suggests rebuilding with `--schema` or `--all-schemas`. `graph.json` and the pages stay byte-identical.
- An unverified context write (`context add`, or an import from another source) no longer replaces a verified note for the same concept, link, relation, column, metric or table; keygraph keeps the verified row and reports a warning. Only re-importing the same context file can update its own rows, and a verified write still replaces anything. Reading a YAML context file without PyYAML now fails with a clear message instead of a raw ImportError.
- Join paths now flag many-to-many hops (including partial composite-key hops) as fan-out and rank them lower, the same as one-to-many hops, in the CLI, MCP and explorer.
- Dev mode, off by default, to study how agents use keygraph and why it answered as it did. `keygraph dev on|off|status|clear|note`, `dev report [--json] [--since] [--session]` and `dev export FILE[.gz]`, or `KEYGRAPH_DEV=1|0` (overrides the marker). When on, it records under `<out>/dev/`: every MCP call, resource read and CLI command (arguments, timing, answer inline up to 16 KB or its hash, size and approximate tokens), the decisions behind an answer (name resolution rule, search scores, path candidates and why one won), and a trace per build (`load`, `scan`, `render`, `profile`, `probe`, `code index`, `queries import`) with every inference candidate kept or rejected and its reason, plus mirror and hub decisions. The MCP server gains a `dev_note` tool, listed only if dev mode was on when it started, and `keygraph dev note` is its CLI twin; they attach the user's question, which keygraph cannot otherwise see. Database row values, profile values, SQL literals, secrets, connection URLs and `--cmd` templates are never recorded; table and column names and agent-written text (search queries, notes, `query_submit` context) are, with secrets masked. `keygraph doctor` gains a `dev_mode` line. With dev mode off nothing is written and `graph.json`, the pages and every command and MCP answer stay as they were, except that `doctor --json` gains a `dev_mode` check (and the MCP check counts 16 tools when dev mode is on at server start). The report groups CLI commands from separate shells into sessions by a 10-minute idle gap; the dev folder and its files are private (0700 and 0600). See `docs/dev-mode.md`.
- Fixed: unquoted secrets such as `password=x`, `db_password: x`, `client_secret=x`, `auth_token=x` and `DB_PASS=x` are now masked in the query log (also with `--keep-literals`) and in the code index. Credentials after `Bearer`, and after `Basic`, `Token` or `Digest` in an `Authorization:` header, and values of dotted keys such as `conn.password` are masked too. Column references such as `a.token_id = b.token_id` are left alone.
- Secret masking in the query log and the code index is now linear-time on long tokens (a 20 KB unbroken token took several seconds before, now under 0.1 s). Unquoted-secret masking leaves code alone: values that start with `(`, `[` or `{`, call or attribute expressions and constant names are not masked.

## 0.3.3 - 2026-11-12

- Continuous integration on GitHub Actions: Python 3.11, 3.12 and 3.13, each with a core-only install (no extras) and with all extras; the README quickstart and `keygraph doctor` on the demo; ruff; a build with `twine check`. Tagged versions publish to PyPI through trusted publishing. The test suite skips tests that need an optional library when it is missing.
- A bare table name that also exists in mirror or copy schemas now resolves to the original table instead of failing as ambiguous (`keygraph path customers shipments --dir examples/shop/out` from the README works again). Names that exist in two or more original schemas are still ambiguous, and mirror tables stay reachable by `schema.table`.
- Agent setup: `setup/SETUP.md` is a protocol any coding agent can follow from the repository URL. The agent detects the database and its own harness, asks the user up to six questions, installs keygraph, builds the map with the chosen extras, connects the MCP server, adds standing instructions, and verifies the result. Per-harness files cover Claude Code (also with DeepSeek, z.ai GLM or other backends), Codex, Cursor, ZCode, OpenCode, Unsloth Studio and other MCP clients, and the CLI for agents with no MCP.
- `keygraph doctor [--json] [--report FILE]` checks Python, the extras, the built map, a join-path query and the MCP server's tools. It prints the MCP launch command with absolute paths, and exits 1 on a failed check. `--report` writes an environment block for bug reports with no table names, SQL, values or home paths.
- `setup/BUG_REPORTS.md` and a GitHub issue form: how agents tell a keygraph bug from a local problem, redact it, look for duplicates, and open an issue only after the user says yes.

## 0.3.2 - 2026-11-04

- Inference prefers a related schema (`app` -> `ods_app`, `app_v2`) when a column's candidates are all in other schemas, and schemas can be declared copies by glob (`copies: ["ods_*"]` in the context or overrides file, `--copy-schema GLOB` on `scan`, `load` and `code index`): the code index prefers non-copy tables and inference prefers non-copy targets.
- SQL Server adapter: every metadata column is named in the query, so command tools that return rows keyed by column name (instead of tuples) read columns, keys and indexes instead of empty rows.
- Inference for databases without foreign keys. A table with no primary or unique key but an `id` column is treated as keyed on `id` as a link target (evidence "assumed key", scored 0.1 below a real primary key; no index is invented).
- Log tables: in `<base>_log`, `_logs`, `_history` and `_audit` tables, `entity_id`, `record_id` and `object_id` point at `<base>` (same schema, then the schema without a trailing `_log`, then a single unique match elsewhere).
- Relations between original tables are copied onto their copies in a mirror schema when the copy has none (confidence x 0.95, `source` "mirror"). Mirror tables stay out of areas as before.

## 0.3.1 - 2026-11-04

- Inference matches a column to a sibling table that shares this table's name prefix: `ad_campaign_banners.campaign_id` -> `ad_campaigns`, `promo_banner_stats.banner_id` -> `promo_banners`.
- Links seen in code: equality joins in SQL found by the code index (`code_joins`, needs sqlglot) and in logged queries become evidence at render time. An edge between the same columns rises to confidence 0.95; otherwise a new inferred edge with `source` "code" is added (`keygraph.code_links.merge_code_joins`).

## 0.3.0 - 2026-11-04

- Code index (`keygraph code index | where | what | stats`): links source code to the tables and columns of a built graph, read as text and never executed. Built-in rules for Doctrine, SQLAlchemy, Django, TypeORM, Prisma, JPA/Hibernate, GORM and Rails; SQL in string literals and `.sql` files, parsed with sqlglot (`keygraph[code]`) or matched by table name without it; uses of declared properties with a common-name guard; every link carries its rule and a confidence. Incremental re-index by file hash; names that match no table are reported as unresolved.
- User pattern files (`code-patterns.yaml`) for in-house framework conventions, with the same engine as the built-in rules.
- Query log (`keygraph queries add | import | top | slow | for | search | show | stats`): SQL that was run, its timing, who ran it and the business question, grouped by fingerprint (a regex normaliser; sqlglot is not used for fingerprints), linked to tables and columns (with roles filter, join, group, read and write when sqlglot is installed), with median, p95 and the recent trend. Literals are masked unless `--keep-literals`; secret-looking values are always masked.
- MCP tools `code_where`, `code_what`, `query_for`, `query_top`, `query_search` (read-only) and `query_submit`, the only tool that writes, and only to the query log.
- Explorer and table pages: "Used in code" per table and column, an "in code" count per table in the area panel, and with `--queries` the most-run queries per table. Code snippets appear only with `--snippets`.
- The shop demo gains a fictional app (`examples/shop/app`) and query log (`examples/shop/queries.jsonl`).

## 0.2.0 - 2026-11-03

- Question-first explorer views: Areas, Area, Path, Table, Column and Search, with a canvas limit of 40 boxes, 25 tables shown first in large areas, and groups of more than 8 relations collapsed.
- Hubs (top 1% by incoming relations, or 60% or more from role columns such as `created_by_id`) shown as labels, and business areas grouped deterministically, with curation through an `areas:` block in the context file.
- Mirror schemas detected and kept out of areas, hub counts and join paths (`--include-mirrors` restores them).
- Join path ranking with penalties for hub, fan-out (one-to-many) and log, archive or scratch tables, and fan-out warnings in the output.
- Agent documents written with each build: `areas/index.md`, `areas/<area>.md` with Mermaid ER diagrams, and `tables/<schema.table>.md`.
- New commands `areas` and `area`; `--json` on query commands; `--include-mirrors` on `path`, `areas` and `area`.
- Value profiles (`keygraph profile`): bounded sampling, null rate, ranges, top values, pattern hints, flags for undocumented or unseen status codes, and the PII rule that stores no raw values for personal data.
- Source adapters: MySQL/MariaDB, PostgreSQL, SQLite, SQL Server, ClickHouse, Metabase, MongoDB, information_schema dumps and external read-only commands, all limited to read-only access.
- MCP server (`keygraph mcp`) with nine read-only tools and two resources.
- Design system, logo and README visuals; fictional demo webshop in `examples/shop`; "How keygraph works" PDF.
- README, AGENTS.md, llms.txt, CITATION.cff and package metadata for discoverability.
- Python 3.11 works again (the CLI failed to import, and `context add --kind ... key=value` was rejected).
- Search leaves short words and stopwords out of prefix matching and ranks whole-phrase hits higher, so a status label such as "in transit" finds its column first.
- Malformed curation entries (area rules without a name or match, `hubs:` or `mirrors:` that are not mappings) become build warnings instead of crashes.
- `keygraph.html` carries a Content-Security-Policy; the MCP server closes its database handles on errors, reads older `keygraph.db` files, and caps `neighbors` depth at 3.
- Mermaid diagrams use safe entity names (no leading digit, ASCII only) and say when an area's diagram shows only its 25 most connected tables.
